# 기존 H2 파일을 MySQL로 옮기기

이 절차는 기존 서버에 저장된 `*.mv.db` 파일이 있을 때 사용합니다. 기존 배포 설정의 기본 위치는 `storage/db/campus.mv.db`입니다. H2 메모리 모드로만 실행했다면 종료 후에 옮길 DB 파일이 없습니다.

1. 기존 서버를 종료하고 H2 파일과 기존 업로드 폴더를 백업하세요. 아래의 `CAMPUS_H2_FILE`에는 백업한 파일의 경로를 입력하세요. 도구는 이 파일을 읽기 전용으로 엽니다.
2. MySQL 8.4에서 UTF-8(`utf8mb4`)로 **새 빈 데이터베이스**를 만드세요. 도구가 프로젝트의 스키마 파일로 테이블을 생성하므로, 대상 DB에 앱을 먼저 실행하면 안 됩니다. 이관하는 동안에는 다른 프로그램에서 대상 DB에 접속하여 데이터를 쓰지 마세요. 이관용 DB 계정에는 이 DB의 테이블·뷰 생성·변경 및 조회·삽입 권한이 필요합니다.
3. JDK 25를 사용해 프로젝트 루트에서 다음 PowerShell 명령을 실행하세요. DB 이름·호스트·사용자·파일 경로는 실제 값으로 바꾸세요.

```powershell
$env:CAMPUS_H2_FILE = 'D:\backup\db\campus.mv.db'
$env:CAMPUS_H2_USER = 'campus'
$env:CAMPUS_H2_PASSWORD = ([pscredential]::new('h2', (Read-Host '기존 H2 비밀번호' -AsSecureString))).GetNetworkCredential().Password
$env:CAMPUS_DB_URL = 'jdbc:mysql://localhost:3306/campus_remarket_import?connectionTimeZone=%2B09:00&forceConnectionTimeZoneToSession=true'
$env:CAMPUS_DB_USER = 'campus'
$env:CAMPUS_DB_PASSWORD = ([pscredential]::new('mysql', (Read-Host '새 MySQL 비밀번호' -AsSecureString))).GetNetworkCredential().Password
.\gradlew.bat -I tools/h2-migration.gradle migrateH2ToMySQL
```

기존 H2 비밀번호가 비어 있었다면 `CAMPUS_H2_PASSWORD`도 빈 값으로 두세요. macOS/Linux에서는 같은 환경변수를 설정하고 `./gradlew -I tools/h2-migration.gradle migrateH2ToMySQL`을 실행하세요.

4. 완료 메시지에 이관한 테이블과 행 개수가 표시됩니다. 도구는 기본 키로 각 행을 다시 읽고 원본의 모든 열을 비교한 뒤 커밋합니다. 회원 비밀번호 해시, 상품·주문 번호, 학교 및 판매자 연결, 업로드 파일 경로도 그대로 복사합니다. 기존 DB에 보관한 모든 행이 대상이므로 기존 시연 계정이나 상품도 함께 옮겨집니다. 이전 버전에 결제 키나 영수증·정산 기록이 있으면 이관 도구가 보관용 열과 테이블을 만들어 그 값도 복사합니다.
5. 기존 업로드 폴더를 새 서버의 업로드 위치(기본 `./uploads`, hosted 프로필은 `CAMPUS_STORAGE_DIR` 아래의 `uploads`)로 복사한 뒤 같은 MySQL 설정으로 앱을 시작하세요. 기존 회원으로 로그인하고, 상품 사진 및 거래 기록을 확인한 뒤 팀의 연결 주소를 새 서버로 변경하세요. 백업은 확인이 끝날 때까지 보관하세요.

**중단된 경우**에는 출력된 테이블 이름과 오류 코드를 확인하세요. 지원하지 않는 원본 테이블, 기본 키 충돌, 제약 조건 위반 또는 값이 달라지면 이관을 중단합니다. 복사 중 오류가 발생하면 행 삽입 전체를 롤백합니다. MySQL에서는 테이블 생성이 즉시 커밋되므로 빈 테이블이 남을 수 있습니다. 원인을 해결하고 **다른 새 빈 DB**에 다시 실행하세요. 이미 이관했거나 데이터가 있는 DB는 도구가 거부합니다.

## 이전 버전에서 진행 중이던 주문

기존 MySQL을 그대로 연결하거나 H2에서 옮겼을 때 `PAYMENT_READY`와 `WAITING_FOR_DEPOSIT` 주문은 양측의 거래 화면에 ‘관리자 확인 대기’로 표시됩니다. 이 상태에서는 예약 취소와 거래 완료를 제한합니다. 관리자 화면의 ‘거래 현황 → 거래 정보’에서 해당 주문번호와 약속 금액을 확인할 수 있습니다.

운영 담당자는 원래 상점에서 같은 주문번호·금액의 최종 상태를 대조합니다. 이체가 여전히 가능하거나 상태가 불분명하면 조회 상태를 유지합니다. 미승인으로 종료됐거나 전액 취소된 주문은 `RESERVED`로 돌려 당사자가 예약을 계속하거나 취소할 수 있습니다. 전액 승인된 주문은 `PAID`로 표시한 뒤 실물 전달 후 당사자가 거래를 완료할 수 있습니다. 일부 취소·금액 불일치는 개별 확인이 필요합니다.

확인한 주문 한 건만 아래처럼 갱신합니다. 두 자리표시자를 실제 주문번호와 위에서 확인한 상태로 바꾸세요. 변경된 행이 0이면 현재 주문 상태를 다시 조회하세요. 이 작업은 앱의 거래 상태 한 건만 변경합니다.

```sql
UPDATE trade_orders
SET status = '<확인한 상태>'
WHERE order_id = '<확인한 주문번호>'
  AND status IN ('PAYMENT_READY', 'WAITING_FOR_DEPOSIT');
```
